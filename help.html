Quick start

Type equations in the Equations pane, one per line, in any order, and press Solve. The solver works out which equations must be solved together, finds the unknowns, and fills the Variables pane with the results. Messages go to the Console.

Part of the windowWhat it does
EquationsThe text you solve. Buttons: Solve, Min/Max (optimization), Check (syntax, counts of equations and variables, and dimensional consistency), Help (this page), Open... and Save... (see "Saving your work" below), and Find... (also Ctrl+F or Ctrl+H in the pane). Find highlights every match and counts them, with options for matching case and whole words; Enter and Shift+Enter step through them, Replace and Replace all change the text, and Ctrl+Z undoes a replacement. Formatted shows the equations as mathematics, for reading and for reports (display only; click Text to edit again): T_1 is shown with the subscript 1, T_1_2 with the subscripts 1,2, m_dot and Q_dot_in with a dot over the letter, v_bar and n_hat with a bar or a hat, T_star as T*, Greek names (eta, sigma, Delta_T, DELTAP) as Greek letters, a/b as a fraction, x^2 as a power, and sqrt() and abs() with their signs; function calls, unit tags and the lines inside function, ode and duplicate blocks stay as text, and comments are left out. Copy copies all the equations, and clicking one equation copies only that one: pasted into Word, each becomes an editable Word equation, left-aligned (selecting the equations and pressing Ctrl+C works too); pasted into a plain-text or LaTeX editor, they arrive as LaTeX, one per line. Tab indents by two spaces (all the selected lines, if several are selected) and Shift+Tab unindents; to leave the pane with the keyboard, press Esc and then Tab.
VariablesOne row per variable: Guess (starting value for the solver, default 1), Min and Max (bounds), Unit (display unit), and the solved Value. Edit a Guess, Min, Max or Unit and press Solve again. With Update guesses ticked, each Solve or Min/Max leaves its solution as the new guesses, and each row of a parametric table starts from the row before. Arrays and matrices show a magnifier; click it to see the full contents. When the equations give uncertainties, a ± column shows them, and with Uncertainty ticked, those of the results. The Export... button writes the results to a text file (see "Saving your work").
Parametric TableSolves the system repeatedly while one variable sweeps from Start to End in a number of steps; also shows the tables of ode blocks. The Export... button writes the table shown to a text file (see "Saving your work"), and Clear Table removes it.
PlotPlots table columns (X and Y selectors, line/markers/bar, overlay several curves, Clear Plot). The plot refreshes automatically when you change a selector. Below them: log x and log y axes, Line Straight or Smooth (a spline drawn through the points; only the drawing changes, so for an ode block a smaller output interval is the honest way to a smooth curve), Colors Light (the default, for reports) or Dark, and Text A− / A+ for the size of the numbers and labels; these apply at once and keep overlaid curves. Save image... writes the plot alone, without the controls, as PNG or SVG (see "Saving your work"). With two curves or more a legend shows which is which: drag it anywhere on the plot, and click a name in it to rename that curve; the saved image keeps both.
ConsoleResults, warnings, unit-check findings and errors. A line number in a message (line 12) is a link: click it to select that line in the Equations pane. The Equations pane numbers its lines: a line named in an error is marked in red, and one named in a warning in amber, until the next Solve, Check, table or Min/Max (or until lines are added or removed, which would move them); click a number to select its line. The cursor position (Ln, Col) is shown at the top right of the Equations pane. Below the console is a command line for quick answers; see The console command line.

The console command line

Type an expression in the box under the console and press Enter; the answer appears in the console. Everything the equations can use is available there: every math.js function, the thermodynamic functions, your user functions, and the variables of the last Solve (in SI). x = 2.5 keeps a value for later lines, and ↑ ↓ recall earlier lines. Examples:

enthalpy('water', 300, 101325)          // 112654.9 J/kg
T_ad - 273.15                           // a result of the last Solve, in degC
derivative(x^3 - 12*x, x)               // 3 * x ^ 2 - 12
simplify(2*x + 3*x)                     // 5 * x
5 ft to m                               // 1.524 m (math.js units work here)
lusolve([4, 1; 1, 3], [1; 2])

derivative, simplify and rationalize take the formula with or without quotes. math.js simplification is limited: it does not, for example, cancel (x^2 - 1)/(x - 1). The command line does not change the equations or the results.

The panes are separated by draggable dividers; drag them to resize. A pop-up window (matrix viewer, Min/Max, Save image) closes with the × button, by clicking outside it, or with Esc.

Saving your work

Save... writes one text file, by default with the extension .ses (session). Chrome and Edge show a Save dialog where you type the name; other browsers ask for a file name and put the file in the Downloads folder. The file holds the equations, followed by a closing comment block with the variable settings (Guess, Min, Max, Unit) and, if you pressed Solve and have not edited the equations since, the results. The results are left out when they would be out of date, and the Console says so.

Open... accepts any text file: a .ses file, or a plain list of equations with any extension. The equations go to the Equations pane; if the file has saved settings and results, they are restored in the Variables pane without solving. If you change the equations in a text editor, the settings are still restored but the old results are dropped. Parametric tables and plots are not saved.

Export... (in the Variables pane) writes the results only, for a report: one line per variable with three tab-separated columns, Variable, Value and Unit, in the units shown in the pane (declared units, or the inferred SI unit). It opens directly in Excel and pastes into Word as a table; arrays and matrices are written as [[1, 2], [3, 4]] in SI units. It contains no guesses, bounds or equations. Export and Save use the results of the last Solve (or Min/Max, or of the opened file); after you edit the equations, press Solve again to include results.

Export... in the Parametric Table pane writes the table shown, tab-separated: a header row such as T [K], then one line per row, in the units and digits shown. With several ode blocks, each table comes under its title line (ode block, line 3), with a blank line between tables. After you edit the equations, run the table (or Solve) again first.

Save image... in the Plot pane writes the plot as it looks in the pane (colors, text size, axes, overlaid curves) but without the controls. Choose PNG, a picture whose size is Width x Height pixels times the Resolution (choose 3x for print), or SVG, a vector drawing that stays sharp at any size and can be edited in drawing programs. The size defaults to 800 x 500 pixels; with a larger Text size, labels stay readable when the picture is shrunk to a report column.

a + b = 10
a - b = 2
T = 25 [degC]

Equation syntax

  • One equation per line, with exactly one =. Either side may hold an expression: x^2 + y = 7. Order is irrelevant. The comparisons ==, <=, >= and != are not equal signs.
  • Several on one line. Semicolons separate equations: a + b = 10; a - b = 2. A semicolon at the end of a line is allowed, and inside [ ] a semicolon still separates matrix rows. A block (function, duplicate, ode, if and the like) starts on a line of its own.
  • Real numbers only. A value that comes out complex, such as sqrt(-1), log(-1) or (-8)^(1/3), is an error that gives the line. It usually means a negative value where it should not be. For a real cube root use cbrt(-8), which is -2.
  • Long lines. A line whose ( or [ is still open continues on the next lines, which is handy for tables of data: 
    // copper, Incropera Table A.1
T_tab = [100, 200, 300, 400,
         600, 800, 1000, 1200]
k_tab = [482, 413, 401, 393,
         379, 366, 352, 339]
    Messages give the number of the first line. This works everywhere: equations, functions, ode and duplicate blocks.
  • Definite integrals: integral(expression, x, a, b) integrates the expression over x from a to b, numerically (adaptive Gauss-Kronrod quadrature, to a relative accuracy of about 1e-10). x is a dummy name, used only inside the call; the expression may use other variables, the limits may be unknowns, and a limit may be Infinity. For example, the entropy change of an ideal gas whose cp is a polynomial: ds = integral((a + b*T + c*T^2)/T, T, T1, T2). Check gives the result the units of the expression times those of x. An integral that diverges stops with an error that gives the value of x where it failed.
  • Derivatives of formulas: derivative(expression, x) is worked out symbolically before solving, for example cp = derivative(a + b*T + c*T^2, T) gives b + 2*c*T, and derivative(W, P) = 0 with W written out as a formula finds an optimum. Only written-out formulas can be differentiated; property functions and user functions are computed numerically (for property derivatives use props('d(H)/d(T)|P', ...)).
  • Choosing a value: if(condition, value if true, value if false), for example f = if(Re < 2300, 64/Re, 0.316*Re^(-0.25)). condition ? a : b is the same. Conditions use < > <= >= == != and and, or, not; if() can be nested. Only the chosen value is calculated, so the other may be invalid there (for example a property call outside the fluid's range). Check requires both values to have the same units. For several statements, loops or iterations, write a user function.
  • Comments: // to the end of the line, /* a comment that can span several lines */, or { text between braces } (which may also sit inside a line). To disable an equation, put // in front of it, or enclose several in /* ... */. A /* without its closing */ is an error.
  • String variables: a name ending in $ holds text, for example fluid$ = 'R134a'. Wherever fluid$ appears, the text is substituted, so h = enthalpy(fluid$, T, P) works and the fluid can be changed in one place. The definition must be a line of its own with a quoted constant; strings cannot be computed or concatenated, and an undefined name$ is reported as an error.
  • Variable names: letters, digits and underscores, starting with a letter: T_1, h_fg, Q_dot. Names are case sensitive (T and t differ).
  • Operators: + - * / ^, parentheses, and the element-wise forms .* ./ .^ for vectors and matrices.
  • Functions: every math.js function (see Math functions) plus the thermodynamic functions (see Thermo functions). ln(x) is a natural logarithm (same as log(x)); use log10 for base 10.
  • Constants: pi, e, i (imaginary unit), tau, phi. Physical constants come from constant('name'), for example constant('sigma') for the Stefan-Boltzmann constant or constant('gravity') for 9.80665 m/s2; see the table. (The math.js names such as stefanBoltzmann are unit-valued objects and do not work inside equations.)
  • Arrays: elements are written x[1], x[2], ... (index starts at 1). Each element is its own variable and can be known or unknown. An index can be computed when it is known before solving: x[N] with N = 20 is x[20], and x[1+1] is x[2]. Two indices are written T[2,3]. x[1:N] is the list of elements 1 to N, so sum(x[1:N]), max(x[1:N]) and mean(x[1:N]) work. To write many similar equations, see Repeated equations.
  • Matrices and vectors as values: A = [1, 2; 3, 4] (semicolon separates rows), v = [1, 2, 3]; use inv, det, transpose, lusolve, and so on. They are shown as a magnifier in the Variables pane.
  • Text values (fluid names and property keys) go in single or double quotes: 'water', 'P'.
  • A variable may reuse the name of a math.js function (for example gamma = 1.4); that function is then unavailable in that file. Names of the thermodynamic functions are reserved and produce an error if used as a variable; viscosity, pressure, density, quality, phase and temperature are examples. Pick mu, P, rho, x instead.

Repeated equations

A duplicate block writes its equations once for every value of a counter, which is how node equations are written for finite differences:

N = 20
T[1] = 400
duplicate i = 2 : N-1
  T[i-1] - 2*T[i] + T[i+1] = 0
end
T[N] = 300
  • The block writes equations; it does not run steps. The copies are solved together with all the other equations, in any order. A line such as s = s + x[i] therefore makes no sense here (every copy would define the same s, and the message says so): write s = sum(x[1:N]), or use a user function, where for loops do run in order.
  • Range. duplicate i = start : end, or start : step : end, or a list such as [2, 5, 9]. The range must be known before solving: it may use numbers and variables set to a constant on a line of their own (N = 20, or M = N - 1 after it), but not variables that are solved for.
  • Nesting. Blocks can be nested, for example over i and j for a two-dimensional grid with variables T[i,j].
  • Inside ode blocks. A duplicate block inside an ode block writes derivative lines, initial values and helpers for many nodes (the method of lines; add , stiff when there are many nodes).
  • Inside a duplicate block, the counter is replaced by its value everywhere it appears as a name, so it can also appear in expressions (x[i] = (i - 1)*dx). A duplicate block cannot contain functions, ode blocks or if/for/while, and cannot be used inside a function.

Tabulated data

interpolate looks values up in a table typed into the equations, for data that has no property function (a chart, a catalogue, measurements):

h = interpolate(T_tab, h_tab, T)              // 1-D, linear between the points
h = interpolate(T_tab, h_tab, T, 'spline')    // cubic spline through the points
z = interpolate(x_tab, y_tab, Z, x, y)        // 2-D, bilinear: Z[i, j] is the value at x_tab[i], y_tab[j]
  • Tables. Write a list as [300, 350, 400], directly or in a variable (T_tab = [300, 350, 400]), or use array elements as T[1:N]. A 2-D table has one row per x value and one column per y value: [1, 2, 3; 4, 5, 6] has 2 rows and 3 columns. Elements set in nested duplicate blocks are written Z[1:M, 1:N]. The x and y values must be strictly increasing.
  • Solving through a table. The value looked up can be an unknown: interpolate(T_tab, P_tab, T) = 30 finds T. While the solver searches, values outside the table are allowed; only the solution must lie inside it.
  • Method. Linear by default. The option 'spline' fits a cubic spline (not-a-knot ends, as Matlab's spline): the most accurate for smooth data, exact for cubic polynomials. 'pchip' fits a shape-preserving cubic (as Matlab's pchip): a little less accurate, but it never overshoots, so monotonic data stay monotonic and a property cannot swing outside the range of its values between points, which makes it the safer choice for property tables and measurements. Both have a continuous slope, which also helps the solver when it solves through the table. In 2-D the method is applied along each direction (bicubic). Options can be given in any order: interpolate(T_tab, P_tab, T, 'pchip', 'extrapolate').
  • Outside the table is an error, unless the option 'extrapolate' is given: then a straight line continues the end slope (also for the cubic methods, whose end cubic could run away quickly), and a warning gives each value that fell outside, as in interpolate(T_tab, P_tab, 120, 'extrapolate').
  • Units. The numbers of a table are used as they are, without conversion: keep a table in the units of the quantities it meets (SI, when its values go into property functions or tagged variables). Check requires x to have the units of the x values, and gives the result the units of the table values, when these are known.
  • interpolate works in equations, user functions, ode blocks and the console command line.

User functions

For a calculation that needs steps, choices or loops (an iterated correlation, a piecewise property, a numerical integral), write a function. A function block can sit anywhere in the Equations pane, before or after the equations that use it. It is then called like a built-in function: in any equation, on either side, inside simultaneous blocks (so the solver can work backwards through it), in parametric tables, in Min/Max and in ode blocks.

function y = name(a, b)
  ...statements, one per line...
end

function [y1, y2] = name(a, b)      // several outputs
  ...
end

Inside a function the lines are run in order, from top to bottom, as in Matlab; they are not solved as equations. A statement is one of:

StatementWhat it does
x = expressionAssignment. v[2] = ... sets an element of an array; F$ = 'water' stores text.
if condition
elseif condition
else
end		Runs the first branch whose condition is true. elseif and else are optional.
for i = 1:n ... endRepeats for each element of a vector: 1:n, 0:0.1:1, [2, 5, 9].
while condition ... endRepeats while the condition is true. It stops with an error after 100000 passes.
breakLeaves the innermost for or while loop.
returnLeaves the function; its outputs must already have values.
error('message')Stops the solution with your message and the line number, for example when an input is outside the range of a correlation.
[p, q] = other(x)Calls a function that has several outputs.

Conditions use < > <= >= == != and and, or, not. A ; at the end of a line is allowed, and comments work as everywhere else. if(c, a, b) (see Equation syntax) also works inside functions.

Rules

  • A function sees only its arguments, the variables it assigns, and the string variables of the equations (such as fluid$). It cannot read other variables of the equations: pass them as arguments. This keeps the solver's ordering of the equations correct. Variables inside a function are local and do not appear in the Variables pane.
  • Calls. A function can call math.js functions, the thermodynamic functions, other user functions, and itself (up to 64 calls deep).
  • Units in the header convert values. In function h [kJ/kg] = hw(T [degC], P [kPa]) the arguments arrive in degC and kPa, and the result is read in kJ/kg and stored in SI. This lets you type a correlation in the units of its source. Without a unit tag a value is in SI. Check checks the arguments against the declared units and uses the declared output unit; an output without a unit is not checked (use [-] for a dimensionless output).
  • Several outputs are used on a line of their own: [h2, s2] = st(T2, P2). Each name on the left is a variable (known or unknown), and the body runs once for all outputs. Using such a function inside an expression is an error.
  • Array outputs. A function may return a vector or matrix: v = f(x) stores the whole array and f(x)[2] takes one element.
  • Text arguments have names ending in $: function T = tsat(F$, P), called as tsat('water', P) or tsat(fluid$, P).
  • Names. A function cannot take the name of a math.js function, a thermodynamic function or a variable. if, elseif, else, end, for, while, break, return, function and error are reserved words.
  • Errors give the line in the Equations pane and the chain of calls, for example h(), line 3: g(), line 6: 'q' is not defined here.
  • Safety. The statements are interpreted by math.js; nothing is run as JavaScript, and evaluate, parse, simplify, createUnit, import and config are not available (derivative(expression, x) is, as in equations).
  • Solving through a function. The solver differentiates functions numerically. A function with if branches is piecewise: give the unknowns guesses on the branch where you expect the solution (see Solving and guesses).

Units

All calculations are done internally in SI (K, Pa, J/kg, m, kg, s, ...). Units never change the numerical equations; they are converted at the edges:

  • Inputs. A constant with a unit tag is converted to SI when the equations are read: P = 2 [bar] stores 200000 Pa; T = 77 [degF] stores 298.15 K; L = 5 [ft] stores 1.524 m.
  • Display. A unit tag after any other right-hand side only sets the unit in which that variable is displayed (and used in tables and plots): h = enthalpy('water', T, P) [kJ/kg] shows kJ/kg although the calculation is in J/kg. You can also type a unit into the Unit column of the Variables pane.
  • Tag syntax. The unit goes in square brackets at the end of the line, after a space: mdot = 0.5 [kg/s], h = 25 [W/(m^2 K)], s = 6.5 [kJ/(kg K)], dimensionless [-]. Combine with * / ^ and parentheses.
  • New units. Units that math.js does not know, such as currencies or counts, are declared on a line of their own, then used like any other: 
    units $, euro, person
price = 0.12 [$/kWh]
q = 75 [W/person]
    Each declared unit is independent, with a factor of 1: it combines with the known units ($/kWh displays as $/MWh correctly). Check treats each one as a dimension of its own, and flags adding $ to euros.
  • Conversion factors. A line 1 [$] = 0.88 [euro] defines the unit on the left from the one on the right, which must already be known (declared, or a math.js unit). Either number may be any positive value, and the name on the left needs no units line: 1 [furlong] = 201.168 [m], 1 [k$] = 1000 [$]. The two units then convert into each other in tags, the Unit column and tables, and Check lets them be added. Values are stored in the unit on the right (its base), so with the line above, 10 $ + 5 euro gives 13.8 euro, or 15.68 $ if that variable's unit is $. Units with an offset (degC, degF) cannot be the base of a definition. Names may use letters, digits, _ and the signs $ € £ ¥; a name math.js already knows cannot be declared. An undeclared unknown unit stays an error, so a typing error such as [kpa] is caught.
  • Temperatures. degC and degF are handled as absolute temperatures, with the offset. A difference in degC equals a difference in K, so write differences as T_s - T_inf with both in the same scale. When you display a temperature in degC the shown number is in degC but the stored value stays in K, so use K inside equations that need absolute temperature (radiation, ideal gas).
  • Pitfalls. [C] means coulomb, not Celsius (use degC). [g] is gram, [h] hour, [t] tonne, [in] inch, [mol] mole. Unknown unit names are reported in the Console.
  • Check. The button checks every equation for dimensional consistency, infers the units of variables you did not label, and lists problems, for example adding metres to seconds, taking exp of a dimensional quantity, or passing pressure where a temperature is expected. Units are inferred from the equations (in Q = m_dot*cp*dT with Q, cp and dT known, m_dot gets kg/s), from the arguments of property functions (T in enthalpy('water', T, P) is a temperature) and from the unit tag of an ode state's initial value. A variable that still has no unit and is set by a plain number (N = 20) counts as dimensionless; when there are problems, the message lists these variables, so give a unit tag to those that have units (T = 300 [K]). Variables whose units cannot be inferred are reported as "not checked". The check compares dimensions only: a pressure in kPa used where Pa is meant is not detected. The check is also run when you press Solve.
Thermodynamic functions take and return SI values. If a variable holds a temperature given as 25 [degC], it already contains 298.15, so enthalpy('water', T, P) is correct as written.

Solving, guesses and bounds

  • The solver pairs each equation with the unknown it determines and splits the system into the smallest groups that must be solved together: single equations (solved one after another, as soon as their other variables are known) and simultaneous blocks (solved together), taken in the order in which they can be solved. An equation left without an unknown of its own is a check of consistency. If a variable is not determined, the message names it and the equations that add no new information.
  • Nonlinear blocks use a bounded, damped Newton method with a finite-difference Jacobian, with a Levenberg-Marquardt fallback. It reports honestly when it cannot converge rather than returning a wrong answer. Convergence is judged against the size of each equation's terms, so a balance written 0 = m*(h1 - h2) + Q converges as well as m*h2 = m*h1 + Q, and the iteration continues until the Newton step is negligible, which keeps long chains of node equations accurate. A message that the iteration did not converge gives the line numbers of the equations in that block.
  • Bounds. Min and Max limit the search for an unknown that is solved by iteration (one found together with others, or from an equation that is not written as x = ...): use them to keep the solver on the physical root, such as a positive temperature or a quality between 0 and 1. A value computed directly from other ones is not held to its bounds, but one that lands outside them is reported as a warning. Min above Max is refused.
  • Guess. The default guess is 1 for every variable. Nonlinear systems may have several solutions or none near that guess; set a Guess in the Variables pane and solve again. Good guesses are essential whenever a property function is involved: asking CoolProp for a state far outside the fluid's range raises an error, and the default guess of 1 K is such a state. For example, for a temperature found from an enthalpy, set a Guess near 300 to 600. Update guesses, at the top of the Variables pane, makes the last solution the next start: this keeps a parametric table on the root of its first row, each row starting near the one before. Untick it if a solve lands on the wrong root, then set that guess by hand.
  • Branches. Equations with if(), and user functions with if blocks, are piecewise. The solver follows the slope of the branch where the guesses lie; on a branch where the result does not depend on the unknown (for example a laminar Nusselt number that is constant in Re) it cannot move. Give guesses on the branch where you expect the solution.
  • Min / Max. Bounds keep the iteration inside a physical range (for example, a temperature above 0 K, a diameter above zero). They are applied as limits on every step.
  • Degrees of freedom. You need as many independent equations as unknowns. Too many gives "Over-constrained system"; too few leaves variables undetermined. Parametric tables and optimization need one extra degree of freedom: comment out (//) the equation that defines the swept or free variable.
  • Accuracy. Property values come from CoolProp (Helmholtz-energy equations of state; IAPWS-95 for water). Results are only as good as the correlations you type in and the guesses that select the root.

Parametric tables, plots, optimization and ODEs

Parametric table

  1. Comment out the equation that fixes the variable you want to sweep (so it has one degree of freedom).
  2. Choose that variable in the Var list, then enter Start, End and Steps.
  3. Press Run Table. Each row is a full solution; all variables become columns.
  4. Pick X and Y in the Plot pane. The plot updates when you change any of its settings. Tick Overlay to compare several Y variables on one chart, and Clear Plot to start over. Log axes leave out points with values of zero or below, and the Console says how many.

Min / Max (optimization)

Set up the equations so that the objective is computed from one or more free variables, comment out the equations that fix those variables, then press Min/Max. Choose Minimize or Maximize and the Target (objective) variable, then tick the Free Variables: as many as the degrees of freedom the equations leave (the dialog says how many). Each free variable needs a Min and a Max: they start from the Variables pane, and changes made in the dialog apply to Min/Max only (they are remembered until the page is reloaded). Example with one free variable:

y = z^3 - 12*z + 12
// z = 0        (commented out, so z is free)

The function has a local maximum at z = -2 (y = 28) and a local minimum at z = 2 (y = -4). The search finds one optimum inside the range you give, so narrow the range around the one you want (for example 0 to 4 for the minimum), or tick Multistart.

Example with two free variables: three-stage compression of air with intercooling to the inlet temperature. The work is least when every stage has the same pressure ratio, here 3: P_2 = 300 and P_3 = 900 kPa.

// pressures in kPa, written as plain numbers; R = 0.287 kJ/(kg K), inlet temperature 300 K
P_1 = 100
P_4 = 2700
k = 0.4/1.4
w = 0.287*300*((P_2/P_1)^k + (P_3/P_2)^k + (P_4/P_3)^k - 3)/k
// Min/Max: minimize w, free variables P_2 and P_3, each from 100 to 2700

The result is w = 333.36 kJ/kg. Min and Max are in the unit each variable is displayed in (its Unit in the Variables pane); a variable without a unit uses SI, so a pressure tagged nowhere is in Pa.

Algorithms.

  • BFGS quasi-Newton (the default) follows the slope of the target, estimated from extra solves around each point, and learns its curvature as it goes. It is fast and accurate for smooth problems. With one free variable (and no multistart) Brent's method is used instead, as before.
  • Nelder-Mead simplex compares values only, moving a set of n + 1 points (a triangle for two variables). It is slower and, near a flat optimum, less precise, but it copes with targets that have kinks or noise: if(), interpolate(), ode blocks, or properties near a phase boundary.
  • Golden section: one free variable only.

All the free variables move together in each step. Points where the equations cannot be solved count as worse, so the search backs away from them; it must be possible to solve at the starting point, which is each variable's Guess if it lies within its bounds, else the middle of the range. After the run the Console gives the optimum, the number of iterations and solves, and marks a variable that ended at its Min or at its Max: the optimum is then set by that bound. The results go to the Variables pane, as after Solve.

Multistart. BFGS and Nelder-Mead find a local optimum, the best point near where they start. With Multistart ticked, the search also starts from 7 more points spread over the bounds (always the same points), keeps the best result, and lists the different optima found. If all starts end at the same point, that is good evidence the optimum is the global one. It takes about 8 times as long.

Uncertainty

Give the uncertainty of a value after +- (or ±), on a line that sets a variable to a number:

T_1 = 400 [degC] +- 1 [K]         // in a unit of its own
P_1 = 3000 [kPa] +- 1 %           // a percentage of the value
m = 2.5 [kg] +- 0.01              // in the unit of the value
  • Use. Tick Uncertainty in the Variables pane: each Solve then gives the uncertainty of every variable, in the ± column and in the console. It is off at every visit, since it takes two more solves for each uncertain value. Given uncertainties show in gray.
  • Method. First-order propagation for independent inputs (GUM, JCGM 100:2008, Eq. 10): u(y)2 = Σ (∂y/∂xi u(xi))2. Each sensitivity ∂y/∂xi comes from solving the equations again with xi + u(xi) and xi − u(xi), so it works through property functions, ode blocks, integrals and user functions. The results mean what the inputs mean: standard uncertainties give standard uncertainties, and expanded ones (at 95 %, say) give approximately expanded ones.
  • Where it comes from. Click a result in the ± column to see each input's sensitivity and its share of u2: the measurement worth improving is the one with the largest share.
  • Limits. The estimate assumes each result is nearly linear over ±u. When it is not (near a maximum, across an if() branch or a phase boundary), a warning names the results concerned. Correlated inputs are not handled. The Parametric Table and Min/Max use the given values and give no uncertainties. Initial values in an ode block cannot carry ±: name the value outside the block, T_0 = 400 [K] +- 3 [K], and write T(0) = T_0.
  • On a line name = number, +- always means an uncertainty: x = 3 +- 0.1 is 3, not 2.9. Elsewhere, as in y = x +- 2, it is ordinary arithmetic.

Ordinary differential equations

Write an ode block. It can hold one equation or several linked ones:

ode t = 0 : t_end : 60            // independent variable = start : end : output interval
  q = h*A*(T - T_inf)             // helper, evaluated at every step
  T' = -q/(m*c)                   // one derivative line per state
  T(0) = 400 [K]                  // one initial value per state, at the start
end
T = 320 [K]                       // the value of T at the end: the solver finds t_end
  • Header. ode t = start : end : interval names the independent variable (any name) and the times at which results are reported. The interval is optional (default: 100 equal intervals). Start, end and interval may be variables of the equations, even unknown ones.
  • States. Each y' = expression line defines one state. States can have any names, or be array elements such as T[1], T[2], so several linked equations go in one block; a duplicate block inside the ode block writes them for many nodes.
  • Initial values. Each state needs y(start) = value, given at the start time. A unit tag after a constant converts it to SI, as in the equations.
  • Helpers. A line name = expression is evaluated in order at every step, before the derivatives; helpers appear as columns of the result table.
  • Inside the block you can use the variables of the equations, the thermodynamic functions and your user functions.
  • Results. After the block, each state name is a variable holding its value at the end. Other equations can use it, and the solver can work back through the block, for example to find the end time or a coefficient that gives a required final value. The values at every output time appear as a table in the Parametric Table pane, and the first state is plotted against the independent variable.
  • Accuracy. The default method is the adaptive Dormand-Prince 5(4) method (the method of Matlab's ode45) with a relative tolerance of 1e-9 and an absolute tolerance of 1e-12. The internal steps are chosen automatically and hidden; only the output times are reported. Change the tolerances with , rtol = 1e-7 or , atol = 1e-9 after the header. The tolerances are relative to the size of the values, so for temperatures in K a tolerance of 1e-9 means about 3e-7 K.
  • Stiff problems. When fast and slow processes occur together (many conduction nodes, chemical kinetics), add , stiff to the header: ode t = 0 : 600 : 10, stiff. This uses an implicit method, linearly implicit Euler with extrapolation of order 4 (the method of the SEULEX and LIMEX codes), with tolerances 1e-8 and 1e-10 by default. It takes far fewer steps on stiff problems but is slower than the default method on ordinary ones. The message "more than 200000 steps were needed" suggests it.
  • The one-line form [t, y_ode] = ode45(@(t,y) -0.5 * y, [0, 10], 5) still works for a single equation: the derivative, the time span and the initial value. The result is two arrays (time and y) with 101 points each, computed with the adaptive method.

Because most heat-transfer correlations need only transport properties, the viscosity, conductivity, specific heat, Prandtl number, density, thermal diffusivity, kinematic viscosity, expansion coefficient and surface tension are provided as functions of their own. Water and ice (all phases)

'water' covers solid, liquid and vapor, and 'ice' and 'steam' are the same substance under other names (so enthalpy('steam', T, P) gives liquid water if that is the stable phase). Give a state as usual, by T and P or by another pair, and the stable phase is chosen for you:

  • Ice Ih below the melting and sublimation curves, from the IAPWS equation of state for ice (IAPWS R10-06(2009), Feistel and Wagner): density, specific volume, enthalpy, entropy, internal, Gibbs and Helmholtz energies, cp, cv, volume expansion and isothermal compressibility, from 50 K to the triple point and up to 208.6 MPa (where ice III takes over). Its reference is that of the fluid (IAPWS-95, as in CoolProp: u = s = 0 for the liquid at the triple point), so enthalpy differences across melting and sublimation are the latent heats: h of ice at 0 degC is about -333.4 kJ/kg.
  • Thermal conductivity of ice: k = 612/T W/(m K), 30 to 273 K, the fit of N. S. Wolfenbarger et al. (Data in Brief 36, 107079, 2021) to the published data (there is no IAPWS formulation). It is about 19 % above the older values of Incropera's Table A.3, which remain available as 'ice_incropera'. conductivity('ice', T) may omit the pressure. Thermal diffusivity comes from k, cp and density. Viscosity, Prandtl number, sound speed and surface tension are not defined for ice.
  • Vapor below 273.16 K (at pressures below the sublimation curve) from IAPWS-95, as for the vapor above the triple point.
  • Phase boundaries (IAPWS R14-08(2011)): below the triple point (273.16 K, 611.657 Pa) saturationpressure('water', T) and saturationtemperature('water', P) give the sublimation curve, and enthalpyvaporization('water', 'T', T) the enthalpy of sublimation. meltingtemperature('water', P) and meltingpressure('water', T) give the melting curve of ice Ih; meltingpoint('ice') is the melting point at 1 atm, 273.1525 K.
  • Mixtures: with a quality below the triple point, 0 is ice and 1 is vapor (sublimation). With (P, h) or (P, s), a state between ice and liquid on the melting curve is a mixture whose quality is its liquid fraction (see the example Ice in a drink).

Other solids below their triple points (dry ice, for example) are not available.

Heat transfer correlations

Correlations for forced and free convection, boiling, condensation and friction, and the solutions for fins, transient conduction, conduction shape factors and radiation, as given in F. P. Each function is named after its correlation, so the choice of correlation is visible in your equations.

  • Arguments and results are dimensionless (Re, Ra, Pr, ratios), except the two length scales lc_cylinders and ls_spheres, which take the radii, and the boiling, condensation and blackbody functions, which take and return SI quantities (listed under each one; values with unit tags arrive in SI, and Check checks every argument); their optional g defaults to the standard 9.80665 m/s^2; compute h from the Nusselt number yourself, h = Nu*k/D, with the length the description names (the height L of a vertical plate, A/P of a horizontal one, the gap of an enclosure). Check flags a dimensional argument. Text arguments go in quotes: nu_dittusboelter(Re, Pr, 'heating').
  • Properties are evaluated where the book says: at the film temperature for most external flows, at the free-stream temperature with a surface value for nu_zukauskas and nu_whitaker, at the mean temperature for internal flows, at the film temperature for free convection, with beta = 1/T_f for an ideal gas; for enclosures at the mean of the two surface temperatures.   • Ranges. Outside the range stated by the book the value is still computed and a warning is shown, for the solution only (the solver may pass outside on the way). Correlations are typically within 10 to 25 % of data.

Heat exchangers (effectiveness-NTU)

The effectiveness-NTU relations of Incropera et al., Tables 11.3 and 11.4, as lines to copy into your equations. Every problem uses the same lines for the heat capacity rates and the energy balances (subscripts h and c for the hot and cold fluids, i and o for inlet and outlet), plus the one line for its flow arrangement:

C_h = m_h*cp_h
C_c = m_c*cp_c
C_min = min(C_h, C_c)
C_max = max(C_h, C_c)
C_r = C_min/C_max
NTU = UA/C_min
q = eps*C_min*(T_hi - T_ci)
q = C_h*(T_hi - T_ho)
q = C_c*(T_co - T_ci)

Because the equations are solved together, the effectiveness line also works backward: give the outlet temperature (or q) instead of UA and the solver finds NTU and UA, so the NTU column is needed only if you prefer the explicit form. Properties may be evaluated at the mean temperature of each stream, cp_h = specificheat('water', (T_hi + T_ho)/2, P), with the outlet temperatures unknown; they are found in the same solution. Examples: Cross-flow heat exchanger, Rotary regenerator.

Regenerators

eps_regenerator(NTU_o, C_r, Cr_star, hA_star) gives the effectiveness of a counterflow rotary (or fixed-bed) regenerator, computed from the energy equations of the two gas streams and of the matrix, integrated over the hot and the cold period until the matrix temperatures repeat from one revolution to the next. It works in dimensionless variables only, so the properties, the flow rates and the outlet temperatures stay in your equations, where they are solved together with it: there is no inner iteration on outlet temperatures to set up. The arguments (W. M. Kays and A. L. London, Compact Heat Exchangers; R. K. Shah and D. P. Sekulić, Fundamentals of Heat Exchanger Design, Wiley, 2003, Ch. 5):

  • NTU_o = [1/(1/(hA)_h + 1/(hA)_c)]/C_min, the overall number of transfer units, with hA the convection conductance on each side (h times the matrix surface area exposed to that stream).
  • C_r = C_min/C_max of the two gas streams.
  • Cr_star = C_matrix/C_min, with C_matrix = M_matrix c_matrix N for a rotary regenerator turning at N revolutions per second (for a fixed-bed pair, the matrix mass of one bed over the period).
  • hA_star (optional, default 1) = (hA) on the C_min side over (hA) on the C_max side; its effect is small between 0.25 and 4.

The model neglects heat conduction along the matrix, leakage and carryover, and takes properties as constant within the regenerator (evaluate them at the mean temperature of each stream, as in the example). As Cr_star grows the result approaches the counterflow effectiveness at NTU_o. The Kays and London correlation, fitted to Lambertson's numerical results, is a quick check: it is within 1 % of eps_regenerator for NTU_o from 2 to 10, C_r from 0.9 to 1 and Cr_star of 1.5 or more, and up to 3 % low at NTU_o = 1:

NTU_o = 1/(C_min*(1/hA_h + 1/hA_c))
Cr_star = M_matrix*c_matrix*N_rot/C_min
eps_cf = (1 - exp(-NTU_o*(1 - C_r)))/(1 - C_r*exp(-NTU_o*(1 - C_r)))
eps = eps_cf*(1 - 1/(9*Cr_star^1.93))

Mixtures and phase equilibrium

Mixtures of any of CoolProp's pure fluids, with their boiling and dew points and the compositions of the liquid and the vapor in equilibrium. Two functions, so the model shows in the equations:

  • mixture(...): CoolProp's equation of state for mixtures (of the form of GERG-2008), for fluids whose every pair has parameters in CoolProp: water with ethanol, methanol, acetone, CO2 and others, hydrocarbons, air components, many refrigerants. It handles strongly non-ideal mixtures such as ethanol and water, azeotrope included, and components above their critical temperature, such as CO2 dissolving in water. A pair without parameters is an error, never a silent estimate.
  • idealmixture(...): Raoult's law, yi P = xi Psat,i(T), an ideal liquid solution with an ideal-gas vapor, for any fluids and any number of them. Good for similar molecules (benzene and toluene, a series of hydrocarbons), and badly wrong for others: for ethanol and water its vapor compositions are off by about 20 mass % (see the example), and it has no azeotrope. Every fluid must be below its critical temperature.

Both take the keys of nh3h2o(): mixture('output', 'ethanol&water', 'key1', v1, 'key2', v2, 'key3', v3), with the input pairs T, P, x  |  P, x, q  |  T, x, q  |  T, P, q (two fluids, q = 0 or 1: the liquid or the vapor in equilibrium)  |  P, x, h.

  • Compositions are mole fractions, the convention of phase equilibrium. With two fluids, x is that of the first fluid named; with more, an array of all of them: 'x', [0.3, 0.3, 0.4]. (nh3h2o and the libr_ functions keep the mass fractions of their sources.) massfraction() and molefraction() convert.
  • q is the molar vapor fraction: 0 at the bubble point, 1 at the dew point, -0.001 for a subcooled liquid and 1.001 for a superheated vapor.
  • h, s, u, v are per kg of mixture, on CoolProp's reference states of the pure fluids, so streams of different compositions can be mixed in an energy balance.

Exergy

Physical exergy. exergy (flow, h - h0 - T0 (s - s0)) and exergy_nonflow (closed system, u - u0 + P0 (v - v0) - T0 (s - s0)) take the state as the other property functions do, followed by the dead state T0 and P0; the dead-state properties are those of the same fluid at T0 and P0 (water at 25 °C and 1 atm is liquid). Kinetic and potential exergy, V^2/2 and g z, are added in the equations when they matter. ig_exergy is the same flow exergy per mole for an ideal-gas species of the combustion table.

Chemical exergy. ig_chemicalexergy is computed from the Gibbs energies of the NASA data, by letting the species react with oxygen of the atmosphere to CO2, H2O (vapor) and N2 at T0 and P0, which then expand to their partial pressures in the atmosphere (Moran and Shapiro, Fundamentals of Engineering Thermodynamics, Eq. 13.36). The default atmosphere is theirs (Table 13.4): T0 = 298.15 K, P0 = 1 atm, N2 75.67 %, O2 20.35 %, H2O 3.12 %, CO2 0.03 %, other gases 0.83 % (molar). For methane this gives 830.41 kJ/mol; Moran and Shapiro find 830.17 kJ/mol with their property tables, and list 831.65 kJ/mol for Szargut's standard environment (their Table A-26, Model II). Species with other elements (S, Cl, F, Ar, He) are not covered, since their reference substances are not gases of the atmosphere.

Mixing. ig_mixingexergy(y, y0, T0) = R T0 ln(y/y0) per mole of a gas at mole fraction y, relative to y0. With y0 = 1 it gives the term of a mixture: the total exergy of an ideal-gas mixture, per mole of mixture, is the sum over its components of y_i (ig_exergy + ig_chemicalexergy + ig_mixingexergy(y_i, 1, T0)). For a gas already in the atmosphere, such as the CO2 of flue gas, ig_chemicalexergy('CO2') + ig_mixingexergy(y, 1, T0) equals ig_mixingexergy(y, 0.0003, T0). Example: Exergy of steam, of methane and of flue-gas CO2.

Ammonia-water mixtures (absorption refrigeration)

nh3h2o('output', 'key1', v1, 'key2', v2, 'key3', v3) gives a property of an ammonia-water mixture from three others, all in SI: T in K, P in Pa, x the ammonia mass fraction (overall), q the vapor mass fraction, h in J/kg. The inputs can be T, P, x (any state: subcooled, two-phase or superheated), P, x, q (q = 0 the bubble point, q = 1 the dew point), T, x, q, T, P, q (q = 0 the liquid, q = 1 the vapor in equilibrium at T and P) or P, x, h (as after a throttle). The outputs are T, P, x, h, s, u, v, q, and xl and yv, the ammonia mass fractions of the liquid and of the vapor in equilibrium (both equal x in one phase). As in EES, q is -0.001 for a subcooled liquid and 1.001 for a superheated vapor. For example, the bubble temperature of a 40 % solution at 10 bar (1e6 Pa) is T_b = nh3h2o('T', 'P', 1e6, 'x', 0.4, 'q', 0), or with P = 10 [bar] on a line of its own, nh3h2o('T', 'P', P, 'x', 0.4, 'q', 0).

The model is that of Ibrahim and Klein (ASHRAE Trans. 99(1), 1993, 1495-1502), which EES uses: Gibbs energies of the pure liquids and gases, an excess Gibbs energy for the liquid and an ideal vapor solution. Its tables and equations were checked against the paper: the reference states of Table 1 return their own enthalpy and entropy, and the saturation pressures of the pure components agree with CoolProp within 2 % for ammonia and 1 % for water up to 500 K. The reference state for h and s is that of EES. The phase equilibrium follows the paper's fugacity formulation, with the Poynting factors taken as 1, as the paper allows below 30 bar. Four printed equations are corrected: the second term of the C2 group of its Eq. 7 has a reference temperature, not T; Eq. 15 lacks a factor x; Eq. 17 lacks a plus sign in (E9 + E10 P); and Eq. 41 has a stray last term. Compared with EES (30 states, 230 to 490 K, 0.2 to 100 bar): saturation temperatures agree within 0.8 K up to 360 K and within 1.5 K above, bubble pressures within 0.2 %, vapor compositions within 0.004 and liquid enthalpies within 2 kJ/kg. The enthalpy of an ammonia vapor is 6.0 kJ/kg lower than EES gives, at every temperature and pressure tested; entropy and volume agree. The model's own enthalpy and entropy are consistent at saturation (hfg = T sfg), and its ammonia hfg is 0.7 % above CoolProp's at 1 bar and 0.2 % at 10 bar, so the difference was left in. Above about 355 K the pure-ammonia fugacity that EES uses falls increasingly below what the paper's recipe gives (by 0.03 in its logarithm at 387 K and 0.13 above 450 K, independently of pressure), and the model carries a correction, fitted to EES states, that reproduces it; above 405 K (the critical temperature of ammonia) the paper's Gillespie equation is used, joined continuously. Limits. The range is 0.2 to 110 bar and 230 to 600 K; above about 550 K the saturation pressure of water in the model departs from the true one (4 % at 590 K). Not compared with EES: pressures above 100 bar and temperatures above 490 K. A call takes 0.2 to 15 ms, and the first one after the page loads about 0.1 s.

Ice in a drink, and frost

Water in all its phases with one substance name: ice below the melting curve, liquid above it, vapor below the sublimation curve, all on the reference of IAPWS-95, so the latent heats come out of the enthalpies. The (P, h) input finds the phase too: the second balance ends on the melting line, a mixture with 84 % liquid. See Water and ice.

// Ice in a drink: 50 g of ice from a freezer at -18 degC dropped into 300 g of water at 25 degC (no heat from outside).
// 'water' covers every phase: enthalpy('water', T, P) is ice below the melting curve, liquid above it, on one reference.
P = 101325 [Pa]
m_ice = 0.05 [kg]
m_w = 0.3 [kg]
T_ice = -18 [degC]
T_w = 25 [degC]
h_ice = enthalpy('water', T_ice, P)
h_w = enthalpy('water', T_w, P)
// final state: the energy balance gives its enthalpy, and (P, h) gives the temperature and the phase
m_ice*(h_f - h_ice) + m_w*(h_f - h_w) = 0
T_f = temperature('water', 'P', P, 'H', h_f)
T_f_C = T_f - 273.15
// with 300 g of ice instead, part of it would stay frozen: x_liq is the liquid fraction of the mixture at 0 degC
m_ice*3*(h_2 - h_ice) + m_w*(h_2 - h_w) = 0
x_liq = quality('water', 'P', P, 'H', h_2)
T_2 = temperature('water', 'P', P, 'H', h_2)
T_melt = meltingtemperature('water', P)

h_fusion = enthalpy('water', T_melt + 1e-6, P) - enthalpy('water', T_melt - 1e-6, P) [kJ/kg]
// frost in the freezer: vapor pressure over ice at -18 degC, and the heat of sublimation
p_sub = saturationpressure('water', T_ice)
h_sub = enthalpyvaporization('water', 'T', T_ice) [kJ/kg]

// Water properties: four outputs; T and P arrive in degC and kPa
function [rho [kg/m^3], mu [Pa s], k [W/(m K)], Pr [-]] = water(T [degC], P [kPa])
  TK = T + 273.15
  PPa = P*1000
  rho = density('water', TK, PPa)
  mu = viscosity('water', TK, PPa)
  k = conductivity('water', TK, PPa)
  Pr = prandtl('water', TK, PPa)
end

// Darcy friction factor: laminar 64/Re, else the Colebrook equation iterated with a while loop
function f [-] = colebrook(Re, rr)
  if Re < 2300
    f = 64/Re
    return
  end
  f = 0.02
  n = 0
  while true
    f_new = (-2*log10(rr/3.7 + 2.51/(Re*sqrt(f))))^(-2)
    n = n + 1
    if abs(f_new - f) < 1e-12 or n > 50
      break
    end
    f = f_new
  end
  f = f_new
end

// Nusselt number: fully developed laminar (constant wall temperature), else Gnielinski
function Nu [-] = nusselt(Re, Pr, f)
  if Re < 2300
    Nu = 3.66
  elseif Re <= 5e6
    Nu = (f/8)*(Re - 1000)*Pr/(1 + 12.7*sqrt(f/8)*(Pr^(2/3) - 1))
  else
    error('Re is above the range of the Gnielinski correlation')
  end
end

Simpson's rule with a for loop

A numerical integral of the ideal-gas cp of nitrogen, compared with the exact enthalpy difference. The small difference is the error of Simpson's rule with 20 intervals.

// Simpson's rule with a for loop: integral of cp dT for N2 from 300 K to 1500 K (n must be even)
function q [J/mol] = simpson_cp(T1 [K], T2 [K], n)
  dT = (T2 - T1)/n
  q = ig_cp('N2', T1) + ig_cp('N2', T2)
  for i = 1:n-1
    if mod(i, 2) == 1
      q = q + 4*ig_cp('N2', T1 + i*dT)
    else
      q = q + 2*ig_cp('N2', T1 + i*dT)
    end
  end
  q = q*dT/3
end

  • Put known inputs first and write the relations in their natural form; ordering does not matter to the solver but helps you.
  • When a property call has an unknown argument, give that variable a reasonable Guess before solving.
  • Use quality 'Q' with T or P for saturated states; use T and P for single-phase states.
  • Unit tags change only display, so you can mix [kPa] inputs and [bar] outputs freely.

Limitations

  • Equations are single-line expressions; sequential code goes in user functions. Functions are differentiated numerically, and cannot read the variables of the equations except through their arguments.
  • In an ode block each derivative is an explicit expression; a derivative defined implicitly by an equation must be computed in a user function. Check takes the unit of an ode state from the unit tag of its initial value, but does not check the derivative lines.
  • The range of a duplicate block, and indices such as x[N], must be known before solving; a solved-for variable cannot set the number of nodes.
  • Optimization works within the bounds you give (each free variable between its Min and Max); other inequality constraints are not supported. It finds a local optimum; Multistart makes finding the global one likely, not certain.
  • String variables are plain text substitutions; they cannot be computed, compared or swept in a parametric table.
  • Complex-valued results are not solved for; equations are real-valued.
  • Solid properties are those of Incropera et al., Tables A.1 to A.3, interpolated linearly in temperature; most materials of Table A.3 are given at 300 K only, and density is taken as constant.
  • The page needs an internet connection for its libraries (math.js, Plotly and CoolProp are loaded from CDNs).
